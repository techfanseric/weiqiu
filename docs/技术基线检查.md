## 已有结构

- `src/router/index.ts`：Hash 路由和登录守卫；首页、物料、实验流程、模块、参数、记录、错误日志。没有独立展示页。
- `src/App.vue`：启动 MQTT、注册全局消息处理，并通过 `arco-theme=dark` 固定暗色。
- `src/hooks/dashboard.ts`：首页四块数据、示例、localStorage、按块刷新和派生状态。
- `src/hooks/main.ts`：样本列表、任务统计、设备状态和变量数据。
- `src/mqtt/index.ts`、`monitor.ts`：连接、心跳、发布/订阅、回调注册。
- `src/components/z-gantt/`：已有时间轴及条形组件；全源码搜索未找到其他组件挂载该甘特图的引用。
- `src/assets/main.less`：大量统一的 `--lx-*` 暗色变量，具备主题改造基础；部分页面仍有内联或硬编码颜色。
- `src/module-x6/`、`views/flow/`：流程编辑器，需保持既有交互与浅色可读性。

## 首期应处理的问题

| 问题 | 源码证据 | 对项目的影响与建议 |
| --- | --- | --- |
| 缺数据时自动显示示例 | `hooks/dashboard.ts` 的 `taskMock`、`visionMock`、`experimentMock` 及派生值；`deviceData` 最终始终可回退示例 | 正式大屏须显式区分演示、未知、离线和缓存，设备空态不能伪装正常运行 |
| 当前时间可能被当成数据更新时间 | `initialBlockTime()`、初始化 `now()`、`refreshBlock()` 下发指令后立即 `touchBlock()` | 拆分请求时间、接收时间与业务发生时间；不能将下发成功展示为数据已更新 |
| 四块数据简单合并，旧批次值可残留 | `updateDashboard()` 用对象展开合并；单块消息缺少强制实验范围 | 引入 runId/version/sequence，切换批次清理结果，过滤乱序或跨实验消息 |
| 缺少稳定设备标识与区域关联 | `DeviceStatusItem` 主要使用 name/value/children；模板以 name 为 key | 补 moduleId、regionId、activeSampleIds，避免重名和字符串猜测映射 |
| 单一运行样本不能覆盖并行 | `TaskData.sample` 为单值；步骤只预留名称与索引 | 用样本数组及步骤实例状态表示同一流程的多样本错峰 |
| 甘特图有复用基础但不适合直接上大屏 | `taskbar.vue` 使用 12px 标签和 tooltip；`index.vue` 为滚动区域 | 当前动作常驻，10 行适配，缩放与短步骤聚合；不用悬停补关键内容 |
| 甘特图清空数据不更新 | `index.vue` watcher 仅在 `v && v.length` 时替换本地 tasks | 实验结束或切换后传入空数组仍残留旧条目，实施时必须覆盖该场景 |
| 旧样例与甘特图渲染模型不同 | `home/samples.ts` 是 steps/startTime/endTime，`taskbar.vue` 接收 barList 和相对时间 | 不能直接传递，需要标准化适配及时间单位校验 |
| MQTT 连接状态非明确响应式 | `connected` computed 读取普通变量 client 及其属性 | 通过 connect/offline/close/error 事件维护 ref，驱动大屏失联状态 |
| 全局弹窗会影响无人操作的大屏 | `App.vue` 对 alert 使用 Modal.info，对 error 调用通知处理 | 展示端采用持续告警条及明确状态；操作确认保留在控制端 |
| 固定 flow ID | 看板刷新、模块库和系统初始化均出现 85 | 由环境/部署配置确认，不据此推定现场也固定为 85 |
| 两处既有类型错误 | `hooks/user.ts:36` 调用 `api.user.get`，`:45` 调用 `api.roles.get`，API 未定义这些方法 | 根据真实接口补齐或移除失效调用；本次仅记录，不猜测接口 |
| Node 引擎版本警告 | 安装日志实际 Node 22.11.0，锁定 JSX 插件要求 `^20.19.0 || >=22.12.0` | 选择满足已锁定依赖要求的运行时并记录版本，不为 UI 改造盲目升级全部依赖 |
| dayjs 非直接依赖 | 多处 import dayjs，但 package.json 未直接声明，由依赖树提供 | 后续工程整理时显式声明当前兼容版本，避免间接依赖变化导致构建失效 |

## 数据接口现状

代码已定义实验列表、流程读取、实验记录、物料列表及控制 API。首页刷新调用 `POST /backend/flow/section`，发送流程 ID 与“获取设备参数”等 name 来触发推送；这不是一个已验证可直接读取快照的 GET 接口。本次未触发该按钮。

已见 MQTT 通道包括 `/data/notification/changed`、`/hitbot/lide/plate/status/` 和流程日志。旧协议拼写 `devcie-status`、`finshed` 应在适配层兼容。尚需后端确认快照方式、断线补偿、运行 ID、步骤状态、预计时间、数据单位、质量判定和展示端只读权限。

原代码在启动时连接 MQTT 并发送心跳，新增展示页需检查连接权限和副作用。源码内已有硬编码 broker 登录字段，环境配置也保留在原始 zip 中；不要把此次本地归档理解为可以直接公开共享的仓库。
