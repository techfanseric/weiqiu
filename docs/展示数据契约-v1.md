# 展示数据契约 v1

本次前端新增的完整快照约定，尚待原后端团队确认和实现；不代表已有接口已经具备这些字段。类型和验证代码在 `app/src/display/model.ts`。

## 传输

- MQTT：原主题 `/data/notification/changed`，消息 `{ "type": "display", "data": snapshot }`。
- 可选初始/重连快照：`.env` 的 `VITE_DISPLAY_SNAPSHOT_URL` 指向确认后的同源 GET 接口，直接返回快照对象；使用原会话 Bearer token，不调用流程执行接口来取数据。
- 正式模式只接受 `source: "live"`。演示由明确的 `mode=demo` 在浏览器生成，不订阅 MQTT、不写入正式缓存。
- 每条消息是完整快照，不做缺失字段浅合并。更新批次后旧检测结果消失；无检测结果时省略 `result`。
- 本版本建议 10 秒内发送一次完整快照，每次增加 `sequence` 并更新 `serverTime`。30 秒未收到有效快照，或消息时刻与本机相差超过 60 秒，显示数据过期并停止状态动画及实时问答。现场需对时，并据最终消息频率校准阈值。

## 主要字段

| 字段 | 类型/规则 |
| --- | --- |
| `schemaVersion` | 固定 `1` |
| `source` | 正式固定 `live`，前端演示为 `demo` |
| `runId` | 唯一批次标识，不循环复用 |
| `sequence` | 同一批次单调递增的非负整数 |
| `serverTime` | 生成快照时服务器 Unix 毫秒 |
| `startedAt` | 批次起始 Unix 毫秒，新批次必须晚于已接收批次 |
| `name` | 实验展示名称 |
| `status` | `running / paused / finished / error / idle` |
| `estimatedEndAt` | 可选 Unix 毫秒；仅运行且未来有效时展示预计剩余，暂停或异常显示待估算 |
| `samples` | 0–10 个样本，完整集合；空数组清空时间线 |
| `result` | 可选最近一次有效检测结果，须属于本批样本并带检测时间 |

每个样本：`{ id, steps }`。每个步骤：`{ id, stage, label, start, end, status }`。

- `id` 是步骤实例 ID，循环三次必须是三个不同实例，不能按步骤名合并去重。
- `stage` 限 `prepare / react / detect / wash / dry`，用于展示分组和概念热区。原团队在适配层映射实际模块与工艺步骤。
- `label` 是当前动作的可读中文，例如“第 2 次离心清洗”。
- `start/end` 为用于排程图的展示时刻，`end > start` 且不早于批次开始。未来步骤是计划，已执行步骤应由服务端校正为实际时间；长步骤与检测可以重叠。
- `status` 限 `planned / running / done / error`。完成状态只由有效快照决定，不由本机倒计时推断。
- `idle` 可以携带空样本；阶段实际超出 v1 列表时先拓展模型与前端，不能将未知步骤静默归为反应。

结果：`{ sampleId, measuredAt, mean, cv, count, distribution, verdict?, rule? }`。

- `mean` 平均粒径，单位 μm；`cv` 变异系数，单位 %；`count` 非负整数颗粒数。
- `distribution` 为 `{ label, count }[]`，标签为粒径区间；本版本最多 40 组。
- `measuredAt` 在本批开始与本次服务器快照时刻之间；`sampleId` 必须属于 `samples`。
- 只有同时提供 `verdict` 与可追溯 `rule` 时，前端才展示质量判定。缺失规则时文字、图表、问答均不编造合格率或阈值。

## 拒绝与缓存

格式错误、未知 schema、超过 10 样本、重复样本/步骤实例 ID、负数或非有限数值、检测关联错误会被拒绝。相同批次的重复/倒序序号和时间倒退会被拒绝；旧批次不得覆盖新批次。

缓存键为 `weiqiu-display-snapshot-v1`。加载缓存不产生新的更新时间，也不作为“收到实时数据”的证据。断线时保留最后有效数据并标注时间，区域不再动态高亮；无缓存时显示空态。正式与演示缓存隔离。

v1 不从旧 `task/vision/experiment` 无关联数据猜测并行流程。旧操作台仍沿用这些消息及 `devcie-status`、`finshed` 等遗留拼写，不改单边协议。
